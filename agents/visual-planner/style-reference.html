PLATFORM · eID API VARIANT SECURITY · TLS PINNING ERROR CODE · 50001

Add opt-in SSL pinning to the eID SDK's api variant

Mirror the existing EKYC SDK pinning in the eID SDK (Android cic-reader/src/api, iOS CakeNfcID). All failures collapse to a single error code 50001. Pinning is off unless pinningCerts is supplied.

Goal
Opt-in public-key pinning for the eID api variant, with one consistent error code across Android and iOS.
Approach
Android: OkHttp CertificatePinner · iOS: ported CESNfcX509CertPublicKeyPinner with CESNfc-prefixed internal types.
Stack
Kotlin · OkHttp · Retrofit · Swift · URLSession · CryptoKit · Dart/Flutter bridge

Fail-closed config errors (step 8)
  • Android: non-empty pinningCerts + invalid baseUrl (no host) → CICReadSDK.initialize throws IllegalArgumentException. Garbage bytes cert → IllegalArgumentException("Invalid SSL pinning certificate supplied").
  • iOS: garbage bytes (or an EC cert) → DEBUG fires assertionFailure at init; release: every readCard / sendLogs rejects with CESNfcError.SSLPinningError (50001) — never appears as an unpinned success.
Flutter bridge smoke (step 9)

In component/flutter/cake_eid/example, pass pinningCerts: [<der bytes>] (correct then wrong) into CakeNfcConfig and confirm: correct cert verifies, wrong cert rejects with code 50001 on both Android and iOS — proving the bridge reaches the native pinner.
